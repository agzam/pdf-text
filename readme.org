#+title: pdf-text.el

[[https://github.com/agzam/pdf-text/actions/workflows/run-tests.yml][https://github.com/agzam/pdf-text/actions/workflows/run-tests.yml/badge.svg]]

A reflowed plain-text reading view for PDFs, on top of [[https://github.com/vedang/pdf-tools][pdf-tools]].

* What

~pdf-view-as-text~ opens the PDF you are viewing as text in a companion buffer, on the page the image view shows and as far into it as the window sits down the image. The document outline becomes foldable org headings, each one owning the text of its own section - including the sections that start mid-page, and the ones a paper numbers ("1 Introduction") where its outline names them bare. A book with no outline metadata gets its headings read out of the pages themselves: a dotted section number at body size, or a glyph size the book uses as a heading style on enough pages, with a split number rejoined to its title and a "Chapter 2" eyebrow merged into the title under it.

The buffer is an ~org-mode~ derivative, so folding, sparse trees (~C-c /~), subtree narrowing and export all work on a book. Extracted text is escaped first, so nothing in the PDF parses as org structure.

- ~pdf-view-as-text~ - open (or re-show) the companion.
- ~pdf-text-show-in-pdf~ - jump the PDF back to the page at point.
- ~pdf-text-sync-mode~ - keep the two buffers on the same page, both directions. On by default in a fresh companion (~pdf-text-sync-default~); toggling it off sticks until the book re-renders.

The companion is reused as long as the file on disk has not changed, so re-opening a 600-page book costs a millisecond rather than seconds.

* Why

~pdf-view~ renders pages as images, so nothing a text buffer gives you applies: no soft wrap, no text motions, no isearch, no spell checker, no translate-at-point. The text is right there - epdfinfo serves it - but no one turns it into a buffer that reads like a book and stays in step with the page you are on.

Getting there is more than calling ~pdf-info-gettext~. Extraction engines compute paragraphs, columns and blocks internally and then throw them away before serving text: what arrives is a list of lines with no structure at all. So the reflow rebuilds it from line records read off MuPDF's structured text (~mutool run~ with a walker script the package carries) - where a line ends, how far the next one starts in, how much air sits between their baselines, how big its glyphs are, and which font set them. MuPDF is the extractor because it reads what the page means: it applies ActualText (small caps arrive as words, not letter salad), expands ligatures, reads tracked type without inventing spaces, flags the spaces it does invent, and names the font of every character - none of which poppler's text layer offers. Out of that come paragraphs, list items, quotations, listings kept verbatim, headings at the line they name, running heads dropped, hyphens resolved against the book's own vocabulary, and super- and subscripts rendered as org's ~^{...}~/~_{...}~ - a footnote marker, an exponent, the limits of a big operator - which the buffer displays as real raised and lowered scripts. A footnote marker whose note sits at the foot of its page in smaller type becomes a real org footnote: ~[fn:18-star]~ at the marker, the definition at the page's end, jumpable both ways. Definition lines - and the unmarked small print a page ends on, an author note, an imprint - read dimmed under ~pdf-text-footnote-face~.

Multicolumn regions come back as what the page set. Rows of cells aligned across persistent white gutters - a phonetic-symbols reference, a table of contents with its page-number column, translation pairs - render as org tables, cells padded to their lane, wrapped cells joined into their row, so ~org-table~ commands work on what used to interleave into pseudo-prose. Parallel lane flows - a gender list set three-up, a numbered exercise list split two-up - read each lane to its end, one item per line, in page order even when the text layer serves the right lane first. Facing columns of justified prose reflow as the two independent columns they are.

* How

** Install

Needs Emacs 29.1, pdf-tools with a built ~epdfinfo~ (~M-x pdf-tools-install~) for the view side, and MuPDF's ~mutool~ on ~exec-path~ for the text extraction (~brew install mupdf-tools~, or the mupdf-tools package of your distribution).

#+begin_src emacs-lisp
;; elpaca
(use-package pdf-text
  :ensure (pdf-text :host github :repo "agzam/pdf-text")
  :defer t)

;; straight
(straight-use-package '(pdf-text :host github :repo "agzam/pdf-text"))
#+end_src

** Use

Bind the entry command in ~pdf-view-mode~, and the sync-back inside the companion:

#+begin_src emacs-lisp
(with-eval-after-load 'pdf-view
  (define-key pdf-view-mode-map (kbd "C-c x") #'pdf-view-as-text))

(with-eval-after-load 'pdf-text
  (define-key pdf-text-mode-map (kbd "RET") #'pdf-text-show-in-pdf)
  (define-key pdf-text-mode-map (kbd "q") #'bury-buffer))
#+end_src

In a GUI frame bind ~<return>~ next to ~RET~ if another minor mode (evil-org, say) binds the function key directly - a direct ~<return>~ binding wins before the terminal translation to ~RET~ ever runs.

** Tuning

Everything the rules measure against is a ~defvar~: ~pdf-text-gap-factor~ (paragraph break as a multiple of the leading), ~pdf-text-blank-factor~, ~pdf-text-size-tolerance~, ~pdf-text-heading-height~ and ~pdf-text-heading-max-words~ (what reads as a heading), ~pdf-text-synth-support~ and ~pdf-text-synth-levels~ (how many pages a glyph size must head before an outline-less book folds on it, and how deep), ~pdf-text-monospace-variation~ (what reads as a listing), ~pdf-text-margin-band~ and ~pdf-text-recurring-min-count~ (what reads as a running head), ~pdf-text-script-size~, ~pdf-text-script-raise~ and ~pdf-text-script-drop~ (what reads as a super- or subscript), ~pdf-text-lane-gutter~, ~pdf-text-lane-min-rows~ and ~pdf-text-lane-flows-min-rows~ (what reads as a multicolumn region), ~pdf-text-min-text-fraction~ (below which a document is a scan and the command refuses it).

* Known limits

- Lane detection wants clean gutters: a table whose header cells span two columns, or whose cells cross the white channel, falls back to the old interleave. A two-up alphabetical list with ragged right edges reads as translation pairs and renders as a table of self-contained cells. Lanes of bare digits or operators - a truth table, an equation array - are left to the display-maths machinery.
- An index reads lane-correct now, but a letter heading inside the flow can fold empty when its entries land on the far side of the reorder.
- Code inside prose still breaks the sentence around it, and maths set in a legacy symbol font with scrambled codepoints escapes the display-maths detection. A symbol whose codepoint scrambles into a control character renders as nothing at all - the character would only ever have displayed as line noise.
- Paragraphs are not joined across a page boundary.
- Pseudocode set in proportional type reflows as prose - nothing in the geometry says it is a listing.
- A subscript set at full size, only lowered, reads the same as a symbol font whose boxes hang below the baseline, and stays plain text.
- A footnote converts only when both halves are present: a marker opening the note's block - raised as a record of its own, superscripted, or flat - and the body citing it, as a generated superscript or, for a symbol, as the flat character closing a title. A marker whose note sits on another page stays a superscript; a numeric note the body never superscripts stays a paragraph. An unmarked smaller-type block at a page's foot keeps its text and carries only the dimming face. And a note's own exponents can be flat in the text layer even when the body's are real (Bryson writes ~1010~ in the note under a body that superscripts ~10^{-43}~); no geometry can raise them.
- A scan has no text layer; ~pdf-view-as-text~ names the page counts and refuses rather than opening an empty buffer.

* Development

#+begin_src sh
bb deps    # buttercup into .local/elpa
bb lint    # check-parens, byte-compile with warnings as errors, checkdoc
bb test    # the buttercup suites in tests/
bb ci      # all of the above
#+end_src

Neither the unit specs nor the corpus cases need a PDF or epdfinfo.

** The corpus

Synthetic geometry proves a rule; it never proves that a book renders. Real books cannot go in the repo and no extractor runs in CI, so the geometry travels instead of the PDF: a case under =tests/corpus/= carries a window of pages as line records, plus the rendering of one subject page that a human read once. The suite renders each case from its records and holds it to that golden and to a set of invariants - text survival, mid-sentence breaks, glued tokens (an OCR text layer runs words together, ~ofResearch~, and welds punctuation to the letter after it; verbatim listings and the document's own compounds stay out of the count), outline titles reading exactly once, no heading folding to an empty section. A case budgets the breaks and glued tokens its page carries today, so a regression bites while an improvement passes.

A case may also declare the invariants it breaks, and the key says why. ~:tolerates~ licenses a residual the round accepts and leaves standing; ~:red~ names a defect the page was captured to hold until the unit that owns it lands. Both are exact sets, not floors: the day a declared defect goes, the case fails and says which key to drop, so no declaration outlives its bug.

The tasks that do want a real book:

#+begin_src sh
bb corpus-add BOOK PAGE [SLUG]   # capture a page and its neighbours as a case
bb corpus-accept [SLUG]          # re-render goldens after an intended change
bb corpus-recapture [SLUG]       # re-derive a case (or all) from the book case.eld names
bb corpus-sweep BOOK [FIRST] [LAST]  # rank a book's pages by what they break
bb corpus-audit [FRAGMENT] [LIMIT]   # account for a whole library, one line per book
#+end_src

~BOOK~ is a path or a fragment matched under ~$BOOKS~ (default =~/SyncMobile/Books=). ~$PDF_TOOLS~ overrides where a built pdf-tools is looked for.

A capture proves the book, not just its window: ~bb corpus-add~ renders the whole book, stores the document facts a window cannot establish - the outline, the hyphenation vocabulary, the recurring running-head forms and the folio-merged count, the modal body profile, the heading-height clusters - and refuses to write a case whose window still renders the subject page differently from the book.

** Timing

A performance claim is a number that reruns:

#+begin_src sh
bb perf BOOK             # the render stage by stage: seconds, ms/page, share
#+end_src

~bb perf~ runs the byte-compiled form the package ships as; ~FORM=source~ prices the interpreted penalty, ~PROFILE=1~ adds a CPU self-time profile. The staging mirrors the product pipeline and a run fails if the two ever disagree.

Extraction walks MuPDF's structured text through ~mutool run~ and a walker script embedded in the elisp (so the reader and its walker can never drift apart, whatever a package manager copies where). The walker emits one elisp form per line - measurements aggregated, font runs itemized - which the native reader parses in a fraction of the extraction's own time. Past ~pdf-text-mupdf-pool-min~ pages the book fans out over ~pdf-text-mupdf-workers~ mutool processes, one per stretch of the document, because the walker is compute-bound in mutool's interpreter; a stretch whose worker fails retries synchronously, so the pool can only ever cost speed, never a page. A 409-page book extracts in about a second and renders in about 2.5.
